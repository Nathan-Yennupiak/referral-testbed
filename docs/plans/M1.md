# M1 Common and workload: plan

**Status:** approved by the candidate on 2026-10-21, with amendments (DECISIONS.md D-009 to D-016). Work starts once M0 is accepted, that is once CI has run green on GitHub. Points marked _Interpretation_ are the agent's reading of an amendment and are open to correction.

## 1. Goal and acceptance (SPEC.md Section 14)

Build `common/` (schema, canonical JSON, signing, lifecycle rules, API types), the facility registry with deterministic key generation, and `workload generate`.

Accepted when unit tests pass and the same seed gives a byte-identical workload file.

Out of M1: the replayer, the saturation ramp, the conformance suite and the verifier (all M2).

## 3. Event format and lifecycle (amended, D-009 and D-010)

Every event has the same fields; those that do not apply are `null`, so the canonical form is uniform.

| Field                                  | Rule                                                                                                            |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `schema`, `eventId`, `clientTimestamp` | Always present                                                                                                  |
| `referralId`, `type`, `signer`         | Always present                                                                                                  |
| `fromFacility`, `toFacility`           | Always present; on every event after ISSUE they must equal the referral's current state                         |
| `urgency`, `patientToken`              | ISSUE only; `null` otherwise                                                                                    |
| `redirectTo`                           | REDIRECT only: the new destination, a registered facility other than the current `toFacility`; `null` otherwise |
| `corrects`                             | CORRECTION only, required: the `eventId` of the corrected event; `null` otherwise                               |
| `reason`                               | Short code on REDIRECT, DECLINE and CORRECTION; `null` otherwise                                                |
| `documentHash`                         | SHA-256 of that event's own synthetic document, or `null` if the step has none                                  |
| `signature`                            | Ed25519 over the canonical form of every other field                                                            |

Lifecycle: the SPEC.md Section 5 table, plus:

- **REDIRECT** is signed by the current `toFacility`; the new state keeps `ISSUED` and sets `toFacility` to `redirectTo`.
- **CORRECTION** is appended, never applied in place. It changes no state. _Interpretation:_ `corrects` must name an earlier event of the same referral, the CORRECTION's signer must be that event's signer, and a CORRECTION is allowed in any state, including final states.
- The verifier (M2) reports a corrected event as "original + correction", never the original alone.

## 4. Package `@testbed/workload` (generate only)

`workload generate --seed <n> --config <file> --out <dir>` writes:

- `events.ndjson`: one line per event, `{"offsetMs":…,"event":{…}}`, each line in canonical JSON, sorted by `offsetMs` then `eventId`.
- `registry.json`: the public facility registry, shared by every architecture in the run.
- `manifest.json`: seed, full resolved config, calibration version, SHA-256 of `events.ndjson` and `registry.json`. No wall-clock time, so the manifest is reproducible too.
- `keys/`: facility private keys (git-ignored). The generator signs every event itself; the keys are kept so a run can be audited.

### Region (D-014)

1 teaching hospital, 1 regional hospital and 6 districts (each with 1 district hospital, 4 health centres and 13 or 14 CHPS; 80 CHPS in total). Ids like `TH-001`, `RH-001`, `DH-003`, `HC-012`, `CHPS-014`.

Owners (illustrative, TBD-CANDIDATE until a verified source is found), assigned to specific facilities by a seeded draw:

| Tier                | GHS | CHAG | PRIVATE | TEACHING |
| ------------------- | --: | ---: | ------: | -------: |
| Teaching hospital   |   0 |    0 |       0 |        1 |
| Regional hospital   |   1 |    0 |       0 |        0 |
| District hospitals  |   5 |    1 |       0 |        0 |
| Health centres (24) |  20 |    3 |       1 |        0 |
| CHPS (80)           |  74 |    4 |       2 |        0 |

_Interpretation:_ the health centre and CHPS counts are my concrete reading of "mostly GHS with a few CHAG and PRIVATE". They give every A2 member organisation except NHIA at least one facility.

### Routing (D-011)

Default: up one tier. CHPS → health centre → district hospital → regional hospital → teaching hospital. The CHPS and health centre steps stay within the district with configured probability (default 0.9).

Bypass to the teaching hospital: each lower tier has a configured probability of referring directly to the teaching hospital, an assumption citing Nkyekyer (2000) and Amoah and Phillips (2017). Placeholder defaults: district hospital 0.5, health centre 0.1, CHPS 0.02.

### Calibration (D-012)

- **Anchor:** teaching hospital inbound referrals, about 130 a month at 1x (Surazu and Korsah 2023, Tamale). The Korle Bu maternity figure (about 280 a month, Nkyekyer 2000) is reported as an upper bound, not used for the default.
- **Issuers:** a tier's total issuing rate is proportional to its tier weight times its facility count, `Λ_t = c · w_t · n_t`. The weights `w_t` are assumptions. The constant `c` is solved so that the expected inbound rate at the teaching hospital, after routing and bypass, is 130 a month.
- **Arrivals:** independent Poisson processes per facility over a configured simulated horizon (default 30 days), from a configured epoch (default `2027-03-01T00:00:00.000Z`).
- Scaling (1x, 10x, 100x) is applied at replay time by compressing `offsetMs`, so one file serves every scale.

### Outcomes and placeholders (D-013, D-015)

- At the receiving facility: accept (ACKNOWLEDGE) 82%, decline 12%, called back (REDIRECT) 6%, from Surazu and Korsah (2023). Applied at every receiving tier, an assumption because the figure comes from one teaching hospital. EXPERIMENTS.md will quote the paper's table and wording exactly.
- REDIRECT goes to another facility of the original destination's tier; the redirected referral then draws a fresh outcome. _Interpretation, needs your confirmation:_ the teaching and regional tiers have only one facility each, so a redirect from either goes to the other one (teaching ↔ regional).
- Placeholders, each documented as an assumption in EXPERIMENTS.md: urgency 60% routine, 25% urgent, 15% emergency; after ACKNOWLEDGE, 90% ARRIVAL and 10% NON_ARRIVAL; after ARRIVAL, 50% COUNTER_REFERRAL; 1% of events followed by a CORRECTION; log-normal delays with medians of 30 minutes (acknowledge or decline), 4 hours (arrival) and 3 days (counter-referral), σ = 1.

**Seeds per repetition.** SPEC.md Section 10 asks for a fresh workload seed per repetition, and Section 9 asks that all three architectures see identical traffic. Both hold if repetition _r_ generates one file from seed _s_r_ and replays that same file against A0, A1 and A2.

## 5. Determinism

- **One seeded generator with named streams.** All randomness comes from SHA-256 in counter mode: block _i_ of stream _L_ is `SHA-256(seed ‖ L ‖ i)`. Each purpose (region, owners, arrivals, routing, outcomes, delays, tokens, ids) has its own label, so changing one part of the config does not shift the random numbers used by the others.
- **Keys:** facility private key = `HMAC-SHA256(seed, "facility-key/" ‖ facilityId)`. Ed25519 signatures are deterministic (RFC 8032), so identical inputs give identical bytes.
- **ULIDs:** a 48-bit timestamp from the simulated clock plus 80 random bits from the id stream, using a small encoder of our own tested against the ULID specification.
- **No wall-clock time, locale or platform-dependent APIs** in generation. CI generates the same seed twice and compares SHA-256, and a checked-in checksum for a small reference seed catches drift across platforms and versions.

## 6. Tests

| Area           | Tests                                                                                                                                                                                                                                                                                   |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Canonical JSON | RFC 8785 test vectors (the RFC's examples and the reference implementation's test data, credited in DECISIONS.md)                                                                                                                                                                       |
| Ed25519        | RFC 8032 Section 7.1 test vectors                                                                                                                                                                                                                                                       |
| Signing        | Round trip; changing any single field invalidates the signature (fast-check); field order does not matter                                                                                                                                                                               |
| Schema         | Valid fixtures pass; each malformed field, each wrongly non-null field for the type, and unknown fields are rejected                                                                                                                                                                    |
| Lifecycle      | One test per transition, allowed and rejected (wrong state, wrong signer, unknown facility, mismatched from/to, bad `redirectTo`, bad `corrects`); final states accept only CORRECTION; property test over random event sequences                                                       |
| RNG and keys   | Known-answer tests; stream independence                                                                                                                                                                                                                                                 |
| Workload       | Same seed gives byte-identical files; different seeds differ; every generated referral replays cleanly through `applyEvent`; outcome shares within tolerance of 82/12/6 on a large seeded sample; teaching hospital inbound rate within tolerance of 130 a month; ids and tokens unique |
